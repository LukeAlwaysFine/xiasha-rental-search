# 产品升级决策记录

## 产品定位

从"房源搜索引擎"升级为"AI 租房助手"：发现 → 理解 → 决策 → 提醒。

**核心指标**: 让用户在 5 分钟内判断一套房值不值得联系房东。

## 三个核心改变

1. **地图优先**: 地图替代搜索框成为主交互。拖动地图刷新房源。
2. **LLM 理解房源**: 质量评分、骗局识别、自然语言搜索。LLM 在后台工作，用户看不到"AI"。
3. **持续服务**: 收藏+邮件提醒。租房是高频重复行为。

## 阶段规划

| 阶段 | 时间 | 目标 |
|------|:----:|------|
| 阶段 0 | 现在 | 修 bug：前端去掉 58/Wellcee chip，统一 LLM_BASE_URL 默认值 |
| 阶段 1 | 1周 | 地图拖拽搜索 + 自然语言搜索 + 质量评分 + 贴吧/微博爬虫 |
| 阶段 2 | 2周 | 收藏提醒 + 房源对比 + 区域洞察 + 19楼 + 小红书搜索 |

## 新平台（Tier 1，SSR 复用豆瓣模式）

- 百度贴吧（杭州租房吧）
- 微博超话（#杭州租房#）
- 19楼杭州租房版

三个平台都用 Firecrawl 统一入口，LLM 提取 prompt 不变。

## 不做的事

- 不做用户注册登录（收藏用 localStorage，提醒用邮箱）
- 不做移动 App（响应式单页即可）
- 不做 AI 对话 chatbot
- 不做 58/贝壳（反爬死/有法律判例）

## LLM 成本

DeepSeek V4 Flash，日均 < 7.2万 tokens，成本 < ¥0.10/天。

**Why:** 现有产品管线扎实但用户体验薄弱。地图优先+质量评分+自然语言搜索三项改动就能拉开与豆瓣原生搜索的差距。平台扩展选 SSR 论坛可以零成本复用现有抓取模式。

**How to apply:** 所有功能新增都是增量 diff，不重写现有代码。每个 LLM 调用复用已有的 AsyncOpenAI + thinking=disabled 模式。
